# MongoDB Prefix Export / Import

Node.js utility to export/import only MongoDB collections whose names begin with a configurable prefix, such as `plactu`.

## 1. Requirements

- Node.js 18 or newer
- MongoDB connection strings for Production and Development
- Network access to the selected MongoDB server

## 2. Install

Unzip the project, open Terminal in the project folder, then run:

```bash
npm install
cp .env.example .env
```

Open `.env` and fill in the real Production and Development MongoDB URIs. The scripts read only `.env`; do not put real values in `.env.example` (it is a template that may be shared). Do not put credentials in source files or commit `.env` to Git.

Example URI format:

```text
mongodb://USERNAME:URL_ENCODED_PASSWORD@HOST:27017/?authSource=AUTH_DATABASE
```

If a password contains special characters, URL-encode them. Use the correct database names in `MONGODB_PRODUCTION_DB` and `MONGODB_DEVELOPMENT_DB`. These values decide which database is used (the database name inside the URI is ignored), and the names can differ between environments. Currently they are `roswalt_realty_db` (Production) and `rosewalt_realty_db` (Development). A misspelled name does not cause an error: export finds no collections and import writes to a new, empty database.

## 3. Choose which collection group to handle

In `.env`, set:

```dotenv
COLLECTION_PREFIX="plactu"
```

Only collection names beginning with that exact prefix are exported. For example, `plactu_data` and `plactu_building` match `plactu`; `start` does not.

For another dataset, change the prefix and rerun the command, for example:

```dotenv
COLLECTION_PREFIX="start"
```

No code changes are needed.

## 4. Export from MongoDB

### Export Production data

```bash
npm run export -- --source production
```

### Export Development data

```bash
npm run export -- --source development
```

The script creates a timestamped folder under `exports/`, containing one JSON file per matching collection plus `manifest.json`. The terminal prints the exact output path.

Files are written in MongoDB Extended JSON (EJSON), so types such as `ObjectId`, `Date`, `Decimal128` and `Long` are preserved (e.g. `{"$oid": "..."}`, `{"$date": ...}`). Do not hand-edit these files into plain JSON, or `_id` values will no longer match on import.

## 5. Import into MongoDB

Use the exact folder path printed by the export command.

### Import the export into Development

```bash
npm run import -- --target development --input "./exports/plactu-production-YYYY-MM-DDTHH-MM-SS-SSSZ"
```

Replace the example folder name with the actual folder generated by your export.

### Import the export into Production

```bash
npm run import -- --target production --input "./exports/plactu-development-YYYY-MM-DDTHH-MM-SS-SSSZ"
```

Again, replace the example folder name with the actual folder generated by export.

### Import behavior (important)

- By default, import uses each document's `_id` to **upsert** it: matching `_id` documents are replaced; new `_id` documents are inserted.
- Documents present in the target but absent from the export are **not deleted** in default mode.
- To replace each matching target collection completely, add `--drop`:

```bash
npm run import -- --target development --input "./exports/ACTUAL-EXPORT-FOLDER" --drop
```

`--drop` permanently drops and recreates the matching collections. Use it only when you intentionally want an exact replacement and have confirmed the target and export folder.

The importer checks that every collection in the manifest begins with the current `COLLECTION_PREFIX`. Keep the prefix set to the one used for that export.

## 6. Suggested workflow: Production → Development

1. Set `COLLECTION_PREFIX="plactu"` in `.env`.
2. Run `npm run export -- --source production`.
3. Copy the exact export folder path printed in Terminal.
4. Confirm `MONGODB_DEVELOPMENT_URI` and `MONGODB_DEVELOPMENT_DB` point to the intended development database.
5. Back up the target first: `npm run export -- --source development`. If anything goes wrong, import this backup folder with `--drop` to restore development.
6. Run `npm run import -- --target development --input "./exports/ACTUAL-EXPORT-FOLDER"`.
7. Add `--drop` only if you want to replace all documents in each matching collection.
8. Check the result: the import prints `upserted` (new) and `modified` (replaced) counts for each collection. Their sum should equal the document counts in the export's `manifest.json`.

Without `--drop`, collections that exist only in the target (e.g. `plactu_dashboard_filter_config` in Development) are left untouched.

## 7. Security

- Never commit or share `.env`. Keep `.env.example` limited to placeholders.
- Do not paste MongoDB credentials into source code or README files.
- Use least-privilege database users.
- A connection string/password previously shared in chat or logs should be rotated before reuse.
- Always double-check the target environment before importing, especially when using `--drop`.
